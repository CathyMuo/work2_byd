# HR1 预登记协议：交接重放——搜索智能体的 RL 收益从哪来（pilot）

登记：2026-10-19　分支：`feat/credit-testbed`　配置：`configs/handoff_v1.json`
用户决定（2026-10-19）：启动方向 (b) 的候选 A pilot，用 Qwen2.5-7B-Instruct 与 Search-R1 7B PPO 互相交接。
本文件在看到任何 HR1 结果前冻结。设计来源：`工作二_新方向查新.md` §4（家服本地文档）。

## 1. 问题

Search-R1 7B PPO（记作 **R**）相对它的起点同族模型 Qwen2.5-7B-Instruct（记作 **I**，套用同一个 Search-R1 模板）的 EM 增益，分别来自：
1. **获取**：查到了什么证据；
2. **利用**：拿到相同证据后怎么读、怎么作答；
3. **与证据无关的部分**：保留查询和思考，把证据换成无关文档后剩下的差距。

最直接的先例是 Pass@(k,T)（2604.14877）：小规模、BM25 加干扰段落、交换差异落在噪声带内、没有安慰剂。
我们的做法是：在每个检索轮边界做**逐 token 相同前缀**的交接，检索用开放的 Wiki-18 + E5，用公开的全量 RL 检查点，并配安慰剂臂和“只交接证据”臂。

## 2. 设置

- **题目**：HotpotQA dev 150 + 2Wiki dev 150，按 `sha256(20261020:sample_id)` 排序，不看结局。按 id 和题面排除所有历史题集，**包括 AC1 的 1000 道新题**。
- **采样**：两个策略都用温度 1.0、top_p 1.0（与 RL 训练一致），每个续写分支 k=8。
- **被交接的轨迹**：每题、每个源策略 P ∈ {I, R} 各采样一条 τ_P（种子固定）。记 s_t 为 τ_P 第 t 次观测之后的前缀（s_0 是初始 prompt），T 为 τ_P 的检索次数。
- **交接点**：t ∈ {0, 1, 2, 3} ∩ [0, T]，加上 end（= T）。
- **续写策略**：Q ∈ {I, R}，从 s_t 起用 Q 采样续写，预算按已用次数接着算。Q = P 是自交接，Q ≠ P 是交接。
- **臂**（都在同一个 s_t 上，t ≥ 1 时才有后两种）：

| 臂 | 构造 |
| --- | --- |
| `real` | 原样前缀 |
| `placebo` | 把第 1..t 次观测都换成冻结的他题文档（CT1 的 null 构造，已过滤答案串和支持事实），其余 token 不变 |
| `evonly` | 去掉 P 生成的 `<think>` 文本，只保留每轮的 `<search>查询</search>` 和原观测，重新编码（不再是逐 token 相同，这一点如实报告） |

- **统一模板（2026-10-19 修订，在看到任何结果之前）**：家服实测，两者的 chat template 不同。Search-R1 的系统提示是 “You are a helpful assistant.”，Qwen2.5-7B-Instruct 是 “You are Qwen, created by Alibaba Cloud. You are a helpful assistant.”；词表相同（151,665）。
  因此**两个策略的初始 prompt 都用 R 的 tokenizer 渲染**，即 Search-R1 训练时用的模板，I 套用同一模板。这样所有交接都是逐 token 相同的前缀。
  I 自己原生模板是否相同，单独记为 `instruct_native_template_identical`（预计全为 False），作为局限报告。

## 3. 估计量（都是聚合 EM，按题聚类 bootstrap，数据集内分层，2000 次）

- 交接曲线 H_{P→Q}(t) = 从 τ_P 的 s_t 起，由 Q 续写的平均 EM。
- **总增益** G_end = H_{R→R}(end) − H_{I→I}(end)，以及 G_0 = H_{R→R}(0) − H_{I→I}(0)。
- **end 处 2×2 Shapley 分解**（证据来源 × 续写者）：
  - 获取 = ½[(H_{R→I} − H_{I→I}) + (H_{R→R} − H_{I→R})]
  - 利用 = ½[(H_{I→R} − H_{I→I}) + (H_{R→R} − H_{R→I})]
  - 获取 + 利用 = G_end。
- **与证据无关的部分**：EF = H^{placebo}_{R→R}(end) − H^{placebo}_{I→I}(end)，以及它占 G_end 的份额。`evonly` 的同类量一并报告。
- 描述量：Q 在对方前缀上的格式错误率（malformed / generation_limit），以及模板一致率。

## 4. Go / No-Go（只判一次）

- **G-A1 协议有效**：
  - (a) 鞅检验：对每个 P，H_{P→P}(0) − H_{P→P}(end) 的 95% CI 含 0（自重放无偏）；
  - (b) 证据有作用：H_{R→R}(end) − H^{placebo}_{R→R}(end) ≥ 5 pp，且 CI 下界 > 0。
- **G-A2 精度**：获取、利用、EF 三个分量的 95% CI 半宽都 ≤ 3 pp。
- **G-A3 信息量**（满足一条即可）：
  - (i) EF 份额 ≥ 30%；
  - (ii) 获取或利用的份额 ≥ 60%，且 CI 下界 ≥ 50%。
  - 原设计中的 (iii)（不同 RL 检查点之间的比较）因为厂内只有一个 RL 检查点，**本 pilot 不适用**。
- **Go = G-A1 ∧ G-A2 ∧ G-A3** → 扩到全量（更多题、更多检查点）冲主会。
- 只过 G-A1 和 G-A2 → 不冲主会，交接曲线并入 (a)。
- G-A1 不过 → 交接协议无效，停止。
- G_end 的 CI 含 0（RL 没有可分解的增益）→ 记为 No-Go，原因写明。

## 5. 已知局限

- I 并不是 R 的训练起点：R 由 Qwen2.5-7B base 训练而来，I 是同族的 Instruct。结论限定为“同族未经搜索 RL 的模型 vs 搜索 RL 模型”。
- `evonly` 重新编码后不再逐 token 相同；`placebo` 保留的思考文本可能引用了被替换掉的证据（这是保守方向的偏差）。
- 只有一个 RL 检查点，跨方法比较留到全量阶段。
