# AS1 / U1N 预登记协议：审计工具的灵敏度，以及自然失败上的恢复

登记：2026-11-02（用户同日决定“两项都做”）　分支：`feat/credit-testbed`　脚本：`scripts/run_as1u1n.sh`　分析：`work2/as1u1n.py`
本文件在任何 AS1 或 U1N 运行之前冻结。家服写协议时，只看过 H1 已有的结果（`h1_pooled_u1l`、`h1_robust_u1l`），没有看过任何新臂的输出。

## 1. 为什么做

H1 的结论是“恢复提示修回的状态，约九成能被等长无意义文字复现”。审稿人最可能提两个问题，现有数据都回答不了：

1. **工具灵敏度**：会不会是智能体根本不读插入的文字？如果是，任何提示都和无意义文字差不多，“内容没用”就只是测量工具不灵敏。临床试验里叫 assay sensitivity，需要一个已知有效的阳性对照来证明。
2. **自然失败**：H1 的失败状态是“换一次文档顺序后答错”人为构造的，提示臂也都接在换过顺序的文档后面。文献里的恢复是在智能体自己答错的轨迹上测的，那里的结论是否一样？

## 2. 智能体（固定）

H1 主表的 14 个插入有效的 RL 智能体：

- Search-R1：v0.3 3B PPO、3B GRPO、v0.1 7B PPO、v0.3 7B PPO、7B GRPO、7B IT-GRPO、14B PPO、14B IT-GRPO、32B GRPO；
- ZeroSearch：Llama-3.2-3B、Qwen2.5-7B；
- StepSearch 7B；
- ReSearch 7B、32B。

各自沿用 H1 的源轨迹（不重新生成）、提示格式、harness 和检索部署。这 14 个智能体的源轨迹都是在 4 卡检索下生成的，所以本批次全程用同一套 4 卡检索服务；每次检索都会和源轨迹记下的文档逐条比对。
插入无效的两个（v03_14b_grpo、autorefine_7b）和两个只靠提示的模型不跑。

## 3. AS1：阳性对照

**状态**：取自该智能体 H1 运行（`outputs/u1/<标签>/pcr`）中 E0 逐字复现的状态：
- 全部退化状态（clean 对、perm_1 错；语义口径或原始口径任一成立即算）；
- 稳定状态（clean 对、perm_1 对，两种口径都成立）中按哈希顺序取 100 个；
- clean 错的状态中按哈希顺序取 100 个。

哈希为 `sha256(seed:sample_id|turn)`，与结果无关。选择依据的 y0 和 perm_1 是 H1 已经测过的，不是新臂的结果。

**臂**（都接在 perm_1 的观测之后，插入位置与 H1 相同）：

| 臂 | 内容 |
| --- | --- |
| `clean_a`、`clean_b` | E0 控制，必须逐字复现源轨迹 |
| `perm_1`、`perm1_review`、`perm1_neutral` | 与 H1 相同；用来逐字核对与 H1 运行一致 |
| `perm1_alert` | 告诉智能体“外部检查表明当前思路很可能导致错误答案”，但不给任何关于答案的信息 |
| `perm1_hint` | 告诉智能体“可靠来源给出的答案是 X”，X 为标准答案的第一个别名（神谕提示，不是方法） |
| `perm1_neutral_alert`、`perm1_neutral_hint` | 与 alert / hint 等长（按该智能体的分词器逐 token 对齐）的无意义文字 |

提示原文见 `work2/placebo.py` 的 `ALERT_PROMPT`、`HINT_TEMPLATE`。

**判定**（语义口径为主，原始口径一并报告）：

- **A1 工具灵敏**：合并后，hint − 其等长无意义文字在退化状态上的修复差 ≥ 20 个百分点，且 95% CI 下界 > 0；并且至少 12/14 个智能体各自满足同一条件。
  - 成立：写“智能体会读并利用插入的内容；H1 的结果不是测量不灵敏造成的”。
  - 不成立：先报告哪些智能体对提示不灵敏。这些智能体在 H1 里的“内容没用”改写为“无法判断”，论文主张随之收窄。
- **A2 剂量关系**（描述性，不设门槛）：报告 review、alert、hint 三种内容各自减去其等长无意义文字后的修复差，以及它们在稳定状态上的额外伤害、在 clean 错状态上的额外救回。预期但不预设：review < alert < hint。
- **A3 复现核对**：perm_1、perm1_review、perm1_neutral、clean_a 的续写与 H1 运行逐字相同的比例。低于 99% 时，停下检查后再解读。

## 4. U1N：自然失败

**状态**：与 H1 相同的冻结规则（按 `sha256(seed:sample_id)` 排序，每个数据集取前 150 道可检索的题，Bamboogle 全部，第 1、2 轮）。这是 H1 题目的一个与结果无关的子集。

**臂**（都在原始文档顺序的观测之后，不换顺序）：`clean_a`、`clean_b`、`perm_1`、`review`、`neutral`、`reflect`、`neutral_reflect`。

**估计量**（语义口径为主）：
- **自然失败**（clean 答错的状态）：各臂的救回率；内容效应 = 方法 − 其等长无意义文字；运气基准 = perm_1（换一次顺序）；安慰剂解释比例 = max(无意义文字, perm_1) / 方法。
- **clean 答对的状态**：方法比无意义文字多造成的伤害。
- **全部状态**：方法 − 无意义文字（准确率的净变化）。

**判定**（合并 14 个智能体，按题聚类 bootstrap；每种方法分别判读）：

- **N1 内容能修自然失败**：自然失败上的内容效应 CI 下界 > 0，且估计值 ≥ 3 个百分点。成立时，论文必须写明“在自然失败上，提示内容有实在的修复作用”，并相应收窄标题所表达的主张。
- **N2 有净收益**：全部状态上方法 − 无意义文字的 CI 下界 > 0。成立时，撤回论文中“没有净收益”的说法。
- **N3 主要是运气**：自然失败上安慰剂解释比例 ≥ 2/3。
- **读法**：N1、N2 都不成立且 N3 成立，写“自然失败上结论相同”；N1 或 N2 成立，按上面改写论文；其余情况如实报告为“部分一致”。
- 另外报告：逐个智能体的估计；把智能体当随机样本时的均值和区间（与论文其余部分相同的做法）。

## 5. 停止条件与不可测

- E0 不复现：按 U1L 修订第 7 节记录并排除；任一运行排除比例 > 2% 时，该运行判为不可测，单独报告，不计入判定。
- 检索漂移、worker 失败：停下回报，不改代码。
- 只用推理，不训练。

## 6. 资源

- AS1：每个智能体约 300–550 个状态 × 9 个臂；
- U1N：约 H1 状态数的 37% × 7 个臂。
- 按 U1L 的实测吞吐量，两项合计约为 H1 全部 GPU 时间的四成，在 4×H800 上约 1–1.5 天。先跑完全部 AS1，再跑 U1N。

## 7. 局限

- 神谕提示给出了标准答案，它只用来验证工具灵敏度，不代表任何可部署的方法。
- alert 是“完美的失败检测器”（只在设计上知道哪里失败），它的效果是上限，不代表现有方法。
- U1N 的“自然失败”是指在第 1 或第 2 次检索之后、最终答错的状态；插入发生在作答之前，与 MR-Search 那种作答后反思不同。后者已在 U2 审计过。
