# 进度看板：厂内使用说明

更新：2026-10-27　代码：`work2/board.py`；页面：`progress_board/index.html`；内容：`progress_board/research.json`

看板是一个**只读**的本地网页，分两部分：

1. **研究说明**（给企业导师看的）：
   - 汇报要点（按讲解顺序排好）；
   - 研究问题、方法示意；
   - 已有结果（带图）、否定结果；
   - 时间线、风险、术语。
2. **实时实验**（每 10 秒自动刷新）：
   - GPU 利用率与显存；
   - 当前批次的流水线状态；
   - `outputs/` 下所有运行目录的进度、速度、预计剩余时间、最近更新时间；
   - 点击某一行可以看该运行的日志末尾。

- 只用 Python 标准库，**不联网**，页面不加载任何外部资源。
- 不占 GPU，不写任何文件，可以和实验同时运行。

## 1. 启动

**注意：U1x 等实验正在运行时不要 `git pull`**（worker 发现代码变了会拒绝续跑）。等当前实验跑完再拉取看板代码。

```bash
cd /root/develop/workspace/work2_byd
git pull --ff-only          # 只在没有实验运行时做
export BOARD_PYTHON=/root/develop/persistent-miniconda3/envs/searchr1/bin/python
nohup bash scripts/run_board.sh > outputs/board.log 2>&1 &
```

默认只监听本机 `127.0.0.1:8765`。

- 换端口：`BOARD_PORT=8800 bash scripts/run_board.sh`；
- 停止：`pkill -f "work2.board --host"`。

## 2. 打开页面

- **在厂内这台机器上**：浏览器打开 `http://127.0.0.1:8765/`。
- **从自己的电脑通过 SSH 访问**（推荐，不需要对外开放端口）：

```bash
ssh -N -L 8765:127.0.0.1:8765 <你的账号>@<厂内机器>
```

  然后在本机浏览器打开 `http://127.0.0.1:8765/`。

- 只有在可信的内网里，并且确认需要让别人直接访问时，才用 `BOARD_HOST=0.0.0.0`。页面会显示运行目录名和日志末尾。

## 3. 页面怎么读

| 区块 | 内容 |
| --- | --- |
| 汇报要点 | 6 句话，按“做什么 → 怎么做 → 发现 → 已发表方法 → 对企业的意义 → 现状”的顺序讲 |
| 已有结果 | H1（7/7 成立）、U2（两个已发表方法）、FC1、H3（未成立）、HR2（部分有效）；每张图都可以展开“查看数据表” |
| 当前批次 | U1x 的 9 个步骤：已完成 / 运行中（带进度条和预计剩余时间）/ 未开始 |
| 运行目录 | 状态有：运行中、已完成、失败（显示报错首行）、**可能已停止**（20 分钟没有任何文件更新）；“速度 / 预计剩余”需要看板开着几分钟后才算得出来 |

## 4. 内容更新

研究说明的文字和数字都在 `progress_board/research.json` 里，由家服维护，随代码一起推送。厂内**不要手改**这个文件；拉取新代码后刷新页面即可看到新内容（不用重启看板）。

## 5. 常见问题

- **GPU 区显示“读不到 nvidia-smi”**：看板所在环境里找不到 `nvidia-smi`，其余功能不受影响。
- **某个运行一直显示“可能已停止”**：先看日志末尾；如果进程确实已经退出，按对应实验的指导重跑同一条命令续跑。
- **端口被占用**：换 `BOARD_PORT`。
