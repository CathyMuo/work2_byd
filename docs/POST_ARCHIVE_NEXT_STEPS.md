## 1. 收尾的新增认识

三个已解释 general 修复都伴随后续检索，绝对调用数为 3、2、2；不能据此把
它们叫作“仅重用初始证据的修复”。这也不证明新检索一定因果必要。

pair_3 constraint 用原问题文本作 query 再检索一次，最后重述初始可见的两处
植物属事实。保守记录为“追加检索后重述与初始支持事实重合的证据”。query
等于原问题，不等于它一定等于之前某次实际 query；更不等于返回文档完全相同。
即使事实没有增加，重复暴露/位置/表述的作用也未被排除。因此不将其升级为
“后续检索无贡献”或内部注意力/采纳机制证明；本轮不为此增加消融实验。

pair_3 secondary 的两次成功新检索后，最终请求超预算搜索被拒，属于
budget_search_refusal。最后被拒的 query 含 Judget Club 拼写异常，但它没有
执行检索，不能据此归因为检索命中失败，也不以修复这个拼写作新实验。

4/4 并集继续作为这四个实际起点的已尝试动作恢复见证；不提供 selector。
当前解释结果支持保留“可恢复行为与额外检索/终止决策相互关联”的观察，
不建立泛化优势、知识来源或内部机制结论。

## 2. 厂内可做的一次性历史对账：46 / 52 / 3

这不是 E 归档的前置条件，也不是新方向的工程 gate。若旧记录可定位，做一次
纯 CPU 集合对账；若原始集合无法找回，保留 unresolved，不为凑数重跑 B。

导出完整 dataset/sample_id/target_turn，而不是报告中的短 ID。至少记录：

| 字段 | 用途 |
| --- | --- |
| dataset、完整 sample_id、target_turn | 统一状态单位，避免短 ID/轮次混用 |
| condition、baseline（B1/B2/B3/B5） | 明确条件分支，避免不同分支被叫作同一起点 |
| clean_em、perturbed_em、recovered_em、status | 明确退化资格及成功定义，空答案不算修复 |
| oracle 标识 | 将 B5 与 nonoracle 分开 |
| source_run、source_locator、raw_file_sha256 | 定位实际旧轨迹，不用汇总数生成行 |
| start_token_sha256、spent/remaining calls（若原记录有） | 同状态计数之外的起点/预算证明；缺失就写 unknown |
| eligibility_rule、missing/skip | 样本范围与覆盖；缺记录不能自动填失败 |

在同一全集、同一状态定义、同一资格/成功口径下，分别导出：

```text
N = B1/B2/B3 至少一支实际修复的状态集合
O = B5 实际修复的状态集合
U = N ∪ O
|U| = |N| + |O| − |N ∩ O|
```

46 与 3 的并集最多 49，不可能是 52。输出 N/O/U 的真实 ID 列表、交集、
旧 52 集合中不在 N∪O 的条目，或者指出哪个旧数字来自不同资格/单位/版本。
这是集合一致性；不能因此证明 oracle/nonoracle 恢复共享 post-evidence 起点。
本轮四个新见证不并入旧集合修补数字。

已有 `work2.audit_recovery` 可复用以校验 compact B 转移与原 A3 来源的分数、
覆盖和 gain/harm，但它**没有自动解决这三个旧集合的 ID 对账**。原 B schema
不在家服，厂内用现有只读解析能力导出，不猜字段、不修改原文件、不要求 push。
返回一张集合计数/交集表和差异原因即可，不需要再提交一份 GPU 实验报告。

## 3. 家服的下一项研究工作：独立立项评审，尚未立项

保留唯一候选问题：**在检索预算有限时，能否只用当下可见状态，选择回答、
继续检索或保持原策略，从而改善准确率—成本取舍并控制稳定状态损害？**
这不是把旧 constraint prompt 改个名字。当前只有小样本现象，不宣称创新或
可学习选择器已经存在。需先做最新主文献核验与方法定位，避免重复通用反思、
动态检索、预算控制或停止方法；本文件不提供未经核实的新颖性声明。

立项评审应交付一页假设与协议草案：

| 必须说明 | 最小要求 |
| --- | --- |
| 可观察输入 | 问题、已有历史/当前可见正文、实际已用/剩余预算；不读 gold、终局对错或未来证据 |
| 目标变量 | 独立同状态动作对照中的真实 EM/F1、调用/token 成本和终止；不把模型自述当真值 |
| 基线 | 原策略不干预、generic review、简单预定预算规则，以及文献核验后选定的既有方法 |
| 动作控制 | 在同实际起点比较；限搜/强制作答若加入，明确改变动作空间并配置相应对照 |
| 总体 | 按题冻结代表性开发总体；包括 clean-wrong、stable、无后续搜索等状态，不能只挑退化/修复案例 |
| 评估 | 完整 gain/harm/net、预算/格式失败、覆盖和实际成本；分层但不从分层子样本伪造总体收益 |
| 数据使用 | 当前四题仅作历史动机和工程回归，不训练/挑选择规则，不用它们确认新方法 |
| 确认 | 方法、触发与成本协议冻结后，使用独立未观察题目；与旧 1000 题/机制案例按整题隔离 |
| 停止条件 | 无可观察区分信号、优势被简单基线消除或稳定损害无法控制时记录不立项/停止；不看结果后改门槛 |

先判断这个新问题是否值得做，再讨论代码/样本量/GPU。若立项评审不能提出
区别于强基线、可被反例推翻且不泄漏未来的假设，就不启动新实验。
新协议需要明确记录后才有下一轮运行清单；原 E/F 计划不自动授权它。
不移用其他停止项目的控制器、选题集合或已观察 dev 调参循环。
